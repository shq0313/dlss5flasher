## 需要保留的准确边界

1. **FFmpeg full build 的完整构建资料仍有缺口。** 已取得 FFmpeg 主源码，但原包还静态链接许多外部库。上游版本列表并不等于全部外部库的准确源码、补丁与构建脚本，不能宣称其完整对应源码已全部提供。
2. **PyAV 二进制不能仅按 DLL 自报 LGPL 归类。** 官方 8.0.1-5 配方包含 x264/x265，且 `patches/ffmpeg.patch` 将它们从 GPL 检测列表移出。此补丁不等于更改编码库的原授权。已附原始配方、补丁、相关许可和源码；正式二进制分发前仍需确认组合授权方案，或换成可明确合规的构建并重新验证。
3. **NVIDIA SDK 不是因社区或免费而免许可。** 原许可允许满足条件的应用内对象代码分发，并保留专有使用、分发和商标要求。补充条款的商业发布通知仅针对其规定范围；不据此推导一般许可豁免。文件来源核对不代表已取得任何额外商标审批或独立运行库授权。

本资料包是实际收集材料，不是完整法律合规证明。当前便携包仍标为候选包；未决项没有用 MIT 声明代替，也没有对外声称已经解决。

## 编码方式与 FFmpeg 查找（2026-10-02 补充）

应用现在允许手动选择 NVENC GPU 或 x264 CPU 编码，两者仍通过现有 PyAV 内置 FFmpeg 库输出 H.264。外部 ffmpeg/ffprobe 继续用于媒体信息读取和原音轨合并；支持环境变量明确指定路径、随包查找及 PATH 查找。无需新增 imageio-ffmpeg 或 OpenCV 依赖。

分发资料按“自有代码 MIT、第三方原许可独立保留、对应源码另外提供”组织。这与常见社区项目的组织方式一致，但不把参考项目已经提供下载当成我们所用构建的分发证明。本次没有替换 FFmpeg/PyAV 二进制，因此前述两个材料未决项保持原状态；切换 NVENC 也不移除二进制内已编入的其他组件。
